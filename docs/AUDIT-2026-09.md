# Carson — Audit (September 2026)

*Source read of `main` @ `3c1e3c6`, driven live in Chromium (1512×900 viewport at 2× DPR, plus the repo's own verify drives), with measurements. Fixes marked **Shipped** are in commit `926d622` on `claude/jolly-feynman-0h7xfc`.*

---

## 0. Headline

Carson already has more *expressive* depth than any mainstream editor: a treatment stack, instruments with seeds, a gesture recorder, an exploration trail, CMYK plates, press check. The weak part is the **engine and the stage** underneath: how the canvas is rendered, how objects are positioned, how the viewport scrolls. The worst problems were there: the default poster rendered half off the artboard, a 300dpi A3 held about 560 MB of canvas memory to show a 441 px preview, and zooming either grew the page or pinned the view to the top-left corner. Those are now fixed. The rest of this document ranks what's left.

## 2. Performance and engine — ranked

| P | Issue | Impact | Recommendation |
|---|---|---|---|
| P1 | **History still snapshots the whole canvas as JSON** for most actions. `commitHistory` in `useEditorHistory.ts:177` runs `JSON.stringify(canvas.toObject())` after adding text, aligning, grouping and similar actions. Embedded images are data URLs, so a poster with a few photos stringifies megabytes on every commit and keeps them in memory. | Visible hitch per action on image-heavy posters; memory grows with every step. | Extend the op-log that `pushIncrementalOp` already has: add `add`, `remove`, `reorder` and `patch` ops. Move image bytes out of the scene JSON into the IndexedDB asset store, referenced by `assetId`. |
| P2 | **Autosave re-serializes everything** 2.5 s after any change, and renders a full-canvas `toDataURL` thumbnail every time. | Main-thread stall during editing bursts. | Serialize in `requestIdleCallback`, reuse history snapshots, and generate thumbnails in an `OffscreenCanvas` worker. |
| P3 | **Canvas 2D is the only compositor.** Fabric redraws every object on every frame, and filters run on the CPU (the Copy Machine alone already moved to a worker). | Caps practical layer count and live filter previews. | Short term: enable `objectCaching` more broadly, set `skipOffscreen`, and group static layers. Long term: a WebGL/WebGPU tile compositor. `gpuTiledBlit.ts` is already a start. |
| P4 | **The backstore is capped at 24 MP.** An A2 at 100%+ on retina renders slightly soft (≈0.96×). | Minor softness at extreme zoom on huge posters. | A viewport-clipped renderer that draws only the visible region at full resolution (Photoshop/Figma tiling). The scale helper and anchor math shipped here are the first building blocks. |
| P5 | **`App.tsx` is 5,160 lines and re-renders on every state change**, with about 60 `useState`s at the top level. `InspectorPanel.tsx` is 1,876 lines. | Every slider tick re-renders the whole editor tree. The main chunk is 504 kB (147 kB gzip). | Split state into stores: document, selection, viewport and UI (Zustand or `useSyncExternalStore`). Lazy-load inspector tabs. Keep treatments out of the main chunk. |
| P6 | **Layer rows regenerate thumbnails on sync** (cached, but invalidated on every patch). | Noticeable with 50+ layers. | Throttle thumbnail regeneration to idle time and render only the visible rows. |
| P7 | **Trackpad pinch in the macOS WKWebView shell.** Chromium turns pinch into `ctrl+wheel` (which works), but WebKit sends `gesturestart/gesturechange`. | Pinch zoom probably does nothing in the native Mac app. | Add a `gesturechange` handler that calls the new `zoomAround()`. |
| P8 | **Two verify drives are stale.** `export-png` closes before the download event fires; `component-instances` expects Detach to disappear after unlink. | False reds erode trust in QA. | Update the drive recipes in `.cursor/skills/verify-carson/scripts/drive.mjs`. |

## 3. UI / UX audit

### 3.1 What's working (keep it)
- **Scope badges (`SEL` / `ALL`)** on every instrument. This is the best answer to "what will this button hit?" in any editor.
- **Calm chrome, loud canvas.** Dark neutral panels around a paper-colored poster is the right hierarchy.
- **Treatment chips with seeds, bypass and re-roll.** "Chaos with a leash" is real now.
- **Exploration trail** with thumbnails, Fork and Comps. Better than Photoshop's History panel.

### 3.2 Friction, in priority order

1. **The selection HUD covers the artwork.** The floating Impact / Size / Opacity bar docks directly under the selection, on top of the content you're judging. *Fix:* dock it above the selection by default, flip below only at the top edge, and fade it to 40% while dragging (Figma's pattern). Respect `prefers-reduced-motion` for the fade.
2. **The top bar is ten unlabeled icons of equal weight.** Home, New, Open, Undo, Redo, Save, Save as, Duplicate, Instruments and more all share one size and color, with no grouping. *Fix:* three clusters with 12 px gaps: **File** (a menu button: New / Open / Save / Save as / Duplicate), **History** (Undo / Redo), and **Primary** (Scramble, Export). Collapse File into a single `⌘` menu the way Linear does. Every icon gets a tooltip showing its shortcut.
3. **The inspector mixes three type systems.** Monospace all-caps labels ("SELECTION PROPERTIES" wraps onto two lines), 13 px sans for fields, and 20 px checkbox labels under OpenType. *Fix:* one scale. 11 px / 600 / +0.06em tracking for section labels, 13 px for fields, 12 px for help text. No monospace outside numeric readouts.
4. **Print tab control and label order is broken.** The "Printer's marks" checkbox floats centered on its own row, and its label appears *below* it. *Fix:* a standard `label + control` row, with the checkbox on the left and the label on the right.
5. **Always-visible disabled Group / Ungroup buttons** take up prime inspector space. *Fix:* show them only when they apply, and put them in the selection HUD for multi-select.
6. **The rulers are decorative.** The hatched strips along the top and left look like rulers but show no numbers, units or cursor tracking. *Fix:* real rulers in the document unit (mm at 300dpi, px otherwise), drag-out guides (already supported by `LayoutGuidesOverlay`), and a cursor position marker.
7. **The Home screen is an empty grey field.** It shows small left-aligned text, one button, and "Start from wreck" hidden in the top-right corner. *Fix:* an editorial hero with three large "starting energy" cards (Wreck, Blank A3, Instagram), drag-and-drop image import onto the page, and a recents grid once saves exist. Suggested type pairing: **Archivo Black** (already bundled) for the display line and **Inter** or **Barlow** at 400/500 for UI text.
8. **Instrument labels wrap into 2–3 lines** ("Copy → Scatter → Copy", "Run through copier"). *Fix:* a single-line label with ellipsis, the full description in a hover card with a live thumbnail preview, and a search field at the top of the palette.
9. **Contrast.** Muted label grey on `#2a2a2a` looks close to 4.5:1. Audit the `--muted` token against WCAG AA and raise it to at least `#9a9a9a`.

### 3.3 Accessibility notes
- ✅ `aria-live` status, labelled regions, keyboard layer cycling with Tab, and `prefers-reduced-motion` are present.
- ⚠️ The canvas has `role="application"` but no text alternative for the selection. Announce "Selected: Oversized headline, text, 4° rotation" through the live region on selection change.
- ⚠️ Sliders show values but do not expose `aria-valuetext` with units (°, %, px).
- ⚠️ Focus rings on dark buttons are subtle. Use a 2 px accent ring with a 2 px offset.

| Capability | Carson today | Gap to close | Priority |
|---|---|---|---|
| **Selection tools** | Object selection only | Marquee, lasso, magic wand, and "select subject" (ML) producing *pixel* masks that feed the existing layer mask | Critical |

## 5. Recommended sequence (long-term best path)

1. **Engine first (2–3 weeks):** P1 op-log history with an asset store, P2 idle autosave, P5 state split. Everything later depends on edits being cheap.
2. **Selection → pixels (3–4 weeks):** marquee, lasso and wand writing into the existing `layerMask` bitmap, then a brush engine sharing the same stamp pipeline (`stampsAlongSegment` already exists).
3. **Adjustment and style layers (2–3 weeks):** reuse the treatment registry. An adjustment is just a treatment whose target is "everything below".
4. **GPU compositor (ongoing):** move filter and treatment rendering to WebGL tiles and keep Fabric for interaction and hit-testing only.
5. **UI system pass (1 week, can run in parallel):** fix the type scale, top-bar clusters, HUD placement and real rulers from §3.2.

## 6. Plain-language summary

- **What was slow:** the app painted the poster at full print resolution, doubled for Retina screens, even when it was shown as a small preview. That's like re-printing a billboard every time you move a sticker. It now paints only what the screen can show, so dragging is about 15× faster and memory use is about 30× lower. Exports still come out at full print quality.
- **What was broken:** the drawing library changed how it measures positions (from the center instead of the corner), and Carson never adjusted. That's why the demo poster was cut off and textures landed in the wrong place. Aligning objects and zooming also misbehaved. All of that is fixed.
- **What to build next:** make undo cheaper, add real selection and painting tools, add adjustment layers, then move rendering to the GPU. That order means each new feature lands on a fast, stable base instead of piling onto a slow one.
